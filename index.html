The idea behind ARC

A core for action and reasoning. A system built around it.

ARC began as Action & Reasoning Core. V2 expands that foundation into a system around local AI: installation, supervision and process execution remain separate, so services can be developed, installed and maintained independently rather than coupling every capability into one monolithic runtime.

The goal is graceful failure. If one service crashes, supervision and restart policies should help contain the failure so the rest of the environment can continue where possible. This is a design objective, not a guarantee that the current development build can never go down.

What ARC is for

A useful local assistant, not a cloud-model replacement.

The focus is the system around the model: persistent services, useful tools, controlled execution and access when you're away.

A different goal

Turn a local model into an always-on helper.

Local models often cannot match the strongest cloud models in broad reasoning. ARC V2 is not trying to claim otherwise or replace cloud AI. It is exploring a different kind of assistant: an optional, extensible server-side helper that stays available between your sessions.

That helper could manage files, assist with lightweight coding, research topics and respond through Telegram while you're away — with a local-first design that aims to keep your data under your control.

Design principles

The architecture is the product.

Four principles guide how ARC V2 is structured and where responsibilities belong.

01 / OWNERSHIP

Local-first

Computation, state and services should be able to run locally and remain under the user's control.

02 / COMPOSITION

Service-oriented

Focused services with explicit contracts rather than one monolithic process that owns every capability.

03 / RESILIENCE

Failure containment

Supervised services and restart policies aim to keep an individual process failure from bringing down the entire environment.

04 / FOUNDATION

Linux-native

Built around Linux as the primary operating environment, using system primitives where they fit best.
